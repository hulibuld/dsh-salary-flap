## client.js 分区

ModuleLoader 只给**一个** `factory`，所以不拆文件，靠分区注释切出六段。整份文件的收尾形状照抄 `dsh-peak-scheduler/lib/client.js:1155-1169`（同槽位、实测可用），**不要自己发明**：

```js
window.__ModuleLoader__.load({
  id: '@local/dsh-salary-flap',
  factory: (require) => {
    const module = { exports: {} }
    const exports = module.exports
    const React = require('react')
    const h = React.createElement
    // ── 六个分区 ──
    exports.apply = apply
    exports.inject = ['slots']
    return module.exports
```

`useTick` 的三档周期（T4 实测后定的，比「active 布尔」精细，采纳）：

| 状态 | `active` | `periodMs` | 为什么 |
|---|---|---|---|
| 设置态（无 settings） | `false` | — | 停表，没有可算的东西 |
| 上班前 `before` | `true` | `SETTLE_MS`(2000) | 金额恒 0，但必须继续轮询，否则永远切不到 `working`（金额不变 → 翻牌不翻，等于白算一次） |
| 上班中 `working` | `true` | `SETTLE_MS`(2000) | 立项卡 §4/§9：2 秒一跳，10 秒约 5 次 |
| 收工后 `after` | `true` | `60_000` | 金额已封顶，只需低频探测「跨天/下一班次开始」，不必 2 秒烧一次 |
| 折叠态 | `true` | 按 phase 同上 | 折叠条仍要显示在涨的金额，不能冻结 |

`useTick` 的实现要点（三条都不能省）：
1. **可见性暂停**：`document.visibilityState === 'hidden'` 时 `clearInterval`；`visibilitychange` 回前台先**立刻补一次 tick** 再重装表，否则用户切回来要干等最多 2 秒。
2. **卸载必清**：`useEffect` 的 cleanup 里 `clearInterval` + `removeEventListener`，一个都不能少。
3. **绝对时间重算**：每次 tick 读 `Date.now()` 重新 `calc`，不做 `earned += 时薪/1800` 的累加。累加会在标签页被节流、系统睡眠唤醒、改参数后立刻失真。

## calc 伪代码

口径（立项卡 §4）：日薪 = 月薪 / 每月工作天数；时薪 = 日薪 / 每日工时；`今日已赚 = 日薪 × 进度`，进度 = 已过计薪时长 / 当日总计薪时长。**三个分支全部由一次 clamp 推出**，不写「现在是否在上下班之间」的时刻比较。

```js
const MIN_MS = 60_000
const DAY_MS = 24 * 60 * MIN_MS

function calc(settings, now) {
  // ① 入口卫兵：任何一项不合法都退成「还没上班」的空快照，绝不 throw、绝不 NaN。
  //    月薪 0 在设置态就被拦住、根本跑不到这里；这里是哑防御。
  const empty = { earned: 0, hourly: 0, progress: 0, phase: 'before' }
  const monthly = Number(settings?.monthly)
  const hours   = Number(settings?.hours)
  const days    = Number(settings?.days)
  if (!Number.isFinite(monthly) || monthly <= 0)              return empty
  if (!Number.isFinite(hours)   || hours <= 0 || hours > 24)  return empty
  if (!Number.isFinite(days)    || days  < 1 || days  > 31)   return empty
  if (!Number.isFinite(now))                                  return empty

  // ② 基本量
  const startMin = parseHHMM(settings?.start) ?? DEFAULT_START_MIN   // 540 = 09:00
  const dayPay   = monthly / days                                    // 日薪（封顶值）
  const hourly   = dayPay / hours                                    // 时薪（小字用）
  const totalMs  = hours * 3600 * 1000                                // 当日总计薪时长

  // ③ 先判班次形状：跨午夜的唯一判据是「起点 + 总时长」越过了当天 24 点
  const crossMidnight = startMin * MIN_MS + totalMs > DAY_MS

  // ④ 今天这个上班时刻（绝对时间戳；用本地 Date 构造，跨月/跨年/夏令时由引擎归一）
  const d  = new Date(now)
  const y = d.getFullYear(), mo = d.getMonth(), da = d.getDate()
  const hh = Math.floor(startMin / 60), mm = startMin % 60
  const todayStart = new Date(y, mo, da, hh, mm, 0, 0).getTime()

  // ⑤ 归一到「班次起点」：只有跨午夜班次才可能还处在昨天开始的那个窗口里。
  //    ★ 上界只能拿 now < todayStart 判，**不许再加 `now - yStart < totalMs`**：
  //      那道上界会把 raw === totalMs（下班当刻）连同之后的整段一起挡掉，
  //      夜班 06:00:00 起显示 ¥0.00 + 「还没上班」，钱在用户眼前当场消失（T6 P0 实测）。
  //      旧班次结束到新班次开始之间，靠 ⑥ 的 raw >= totalMs 自然落 after / 封顶。
  let shiftStart = todayStart
  if (crossMidnight && now < todayStart) {
    const yStart = new Date(y, mo, da - 1, hh, mm, 0, 0).getTime()   // da-1 由 Date 自动借位
    if (now >= yStart) shiftStart = yStart
  }

  // ⑥ 三态用**未夹紧的原始偏移**判，夹紧只负责金额：
  //    raw < 0 → 还没到上班点；raw >= totalMs → 收工封顶；其余 working。
  //    这样 09:00:00.000 这个精确瞬间算 working（立项卡 §4 的口径是「上班时间 ≤ 现在」），
  //    而不是被 elapsed <= 0 误判成 before。
  const raw      = now - shiftStart
  const elapsed  = clampNum(raw, 0, totalMs)
  const progress = elapsed / totalMs
  const phase    = raw < 0 ? 'before'
                 : raw >= totalMs ? 'after'
                 : 'working'

  // ⑦ 不取整：截断只发生在 fmtMoney，长度计算全程保留浮点
  return { earned: dayPay * progress, hourly, progress, phase, dailyWage: dayPay }
}
```

> 契约：`{ earned, hourly, progress, phase }` 四键**必须都在**；`dailyWage` 是实现方附加的便利字段（设置摘要、调试用），允许存在，审查时不当作偏离。
> 边界：`raw === 0` → `working` + `progress 0` + `¥0.00`；`raw === totalMs` → `after` + 封顶。两者金额都等于两端值，只有文案与配色不同。

**为什么不能用「现在时刻 < 下班时刻」决定日期归属**：SalaryTick（`app.py:74`）就是这么写的，实测白班 09:00–18:00 在任何时刻（08:00 / 12:00）`progress` 都恒为 1.0——因为白班下班前该条件总成立，窗口被整体挪到昨天，`elapsed` 永远 ≥ `total`。正确做法是上面 ③④⑤ 三步：**先判 `crossMidnight`，再只对跨午夜班次回退一天，且一律用绝对时间戳做差**。跨午夜归一也就此由 `Date` 构造器接管，不需要 `+24h` 之类的分钟数修补。

`trunc2` / `fmtMoney`（截断，不是四舍五入）：

```js
function trunc2(n) {
  if (!Number.isFinite(n)) return 0
  const v = Math.floor(Math.abs(n) * 100 + 1e-9) / 100   // 1e-9：1.15*100 在 IEEE754 是 114.99999999999999
  return n < 0 ? -v : v
}

function fmtMoney(n) {
  const v = trunc2(n)
  const safe = v === 0 ? 0 : v        // 把 -0 归一成 +0，避免出现 '¥-0.00'
  return '¥' + safe.toFixed(2)        // toFixed(2) 保证永远两位
}
```

验证用例（T4 单测、T6 审查共用这张表；月薪 10000 / 8h / 22d / 09:00 上班）：

|---|---|---|
| 日薪 / 时薪 | — | 日薪 454.5454…、时薪 56.8181… |
| 上班前 | 08:59:59 | `¥0.00`，`phase:'before'` |
| 刚上班 | 09:00:00 | `¥0.00`，`phase:'working'` |
| 上班中 | 12:00:00 | 3h/8h → `¥170.45` |
| 收工前 | 16:59:59 | 接近但不足 `¥454.54` |
| 收工 | 17:00:00 | `¥454.54`，`phase:'after'` |

## 持久化

三个键分开存，前缀统一 `dsh.salary-flap.v1.`。分键的理由不只是「干净」：三者更新频率差一个数量级（settings 只在点按钮时写、pos 在拖动结束时写、collapsed 点一次写一次），分键可以只写变的那一个；而且 localStorage 与 Harness 其他插件共用命名空间，不加前缀等着撞键。

| 键 | 值形态 | 首次默认 | 读失败 / 非法值的兜底 |
|---|---|---|---|
| `dsh.salary-flap.v1.settings` | `{"monthly":12000,"hours":8,"days":22,"start":"09:00"}`（JSON 字符串） | 视为**无配置** → 进设置态 | 逐字段校验，坏字段各自回默认；`monthly>0`、`0<hours<=24`、`1<=days<=31`、`parseHHMM(start)!==null` 否则该字段回默认 |
| `dsh.salary-flap.v1.pos` | `{"x":1234,"y":678}`（卡片**左上角**的视口坐标） | `null` → 用 `DEFAULT_INSET` 右下角 | 解析失败 / 非有限数 → `null`；读到但超出视口 → `clampPos` 夹回（只在渲染时夹，**不回写**） |
| `dsh.salary-flap.v1.collapsed` | `true` / `false` | `false` | 非布尔 / 解析失败 → `false` |

约定：
- **首次判定**：`localStorage.getItem(LS_SETTINGS) === null` → 设置态。键存在但解析失败 → **也进设置态**（预填默认值），不要静默拿默认值开跑，否则用户会以为金额是真的。
- 折叠与首次的优先级：没有 settings 时 `collapsed` 一律当 `false`，首次必须能配置。
- 全部读写包 `try/catch`：隐私模式 / 配额满时 `setItem` 会抛，抛了只影响持久化，绝不能让看板崩。
- 值统一 `JSON.stringify` 存字符串（不存裸数字），读到非对象即退兜底。
- 默认位置换算：`x = innerWidth - CARD_W - 24`、`y = innerHeight - 估算卡高 - 96`，再用 `clampPos` 夹一遍（小窗口下不至于跑到屏幕外）。
- `resize` 时重新 `clampPos` 渲染，但不写盘——用户随手缩一下窗口不该把位置永久改掉。
- 键名带 `v1`：将来结构变更升 `v2`，旧键不读、也不主动删（别清理不属于自己的键空间）。

## 翻车点

每条都是「现象 → 根因 → 对策」。第 1 条是本项目最容易造成「插件看起来有毒」的坑，先做对它再写别的。

### 1. pointer-events 吃掉整页点击（头号）

- **现象**：装上看板后，看板以外的界面点不动——聊天输入框点不进、按钮没反应、右键菜单错位；卸掉插件立刻恢复。
- **根因**：`shell.overlay` 是**整帧浮层且条目本身可接收指针事件**。我们的根容器 `position:fixed; inset:0` 铺满整个视口，如果不显式关掉，它会把下面所有 UI 的点击吞掉。
- **对策**：外层容器 `pointerEvents:'none'`，内层卡片 `pointerEvents:'auto'`（两层都要有，缺一层就出事）。根容器上**不要**挂 `onClick`/`onContextMenu`；纯展示子元素（金额、翻牌、小字）不需要单独设，继承 `auto` 即可；折叠横条必须自己 `auto`，否则点不开。同槽位的两份现成实现都是这么写的：`dsh-refresh-restart/client.js:161`（`pointerEvents:'none'`）与 `:137`（`'auto'`）、`dsh-sort-out-the-thoughts/client.js:88`。

### 2. 渲染路径上有会抛的表达式 → overlay 条目被静默退役

- **现象**：控制台没有红字，插件却消失了；`cordis_inspect_query` 里 `salary-flap` 条目不见或 `active:false`。
- **根因**：组件渲染时抛错，宿主把整条 slot entry 退役、不重试。这比白屏更难查——没有报错界面，只剩「什么都没出现」。
- **对策**：所有 `localStorage` 读取、`JSON.parse`、数字解析、`parseHHMM` 一律 `try/catch` 或先校验；`calc` / `fmtMoney` / `slotify` 保证「绝不抛、只返回安全值」；渲染前把数据归一成一定能渲染的形态（字符串、有限数、合法枚举）。组件里不写 `JSON.parse(localStorage.getItem(...))` 这种裸表达式。

### 3. hooks 条件调用 / 三态换顶层组件

- **现象**：切到设置态时白屏或报 `Rendered more hooks than during the previous render`；或金额停住不动。
- **根因**：把三态写成三个顶层组件轮流挂载，或把 `useTick` 放进 `if (phase === 'working')` 里——hook 顺序错位后 React 与宿主整棵树一起报废。
- **对策**：`SalaryFlap` 里的 hook **全部无条件调用**（三个 `usePersisted` + `useTick(active, periodMs)` + `useDrag` + `useReducedMotion`），三态只是 return 里的分支；周期可以按 phase 变（2s / 60s），但 hook 本身不能跳过调用。子组件（`SetupCard` / `RunningCard` / `CollapsedBar`）可以是条件渲染，但它们自己内部也不许有条件 hook。

### 4. 定时器与监听器泄漏

- **现象**：关掉看板后 CPU 仍缓慢上涨；控制台出现 `setState on unmounted`；反复刷新几次后节拍从 2 秒变成 1 秒甚至更快。
- **根因**：`setInterval` / `visibilitychange` / `pointermove` 只注册不清理，或 `useEffect` 依赖数组写空却引用了外部变量。
- **对策**：`useEffect` 的 cleanup 与注册一一对应（`clearInterval` + `removeEventListener`）；拖动把 `move`/`up` 挂到 `window` 后必须在 `pointerup`/`pointercancel`/卸载时移除；effect 依赖写全（`active`、`pos` 等）；定时器一律用 `setInterval` + 绝对时间重算，不用递归 `setTimeout`。

### 5. 翻牌 backface 透出反面数字

- **现象**：翻到一半能看到镜像的数字、重影，或牌面发灰。
- **根因**：漏了 `backface-visibility:hidden`；或 `perspective` 打在每一半而不是牌容器；或没建独立合成层（Safari 上 backface 需要 `translateZ(0)` 才生效）。
- **对策**：四个半页全部 `backface-visibility:hidden; -webkit-backface-visibility:hidden; transform:translateZ(0)`；`perspective:240px` 只写在 `.sf-slat` 上；`transform-origin` 打在接缝（上半 `bottom center`、下半 `top center`）；`preserve-3d` 不要乱加在祖先上。

### 6. 静止上半放错值 → 翻完又跳回旧值

- **现象**：数字先变成新值，闪一下又回旧值，再变新值。
- **根因**：四层角色搞反。**静止上半必须是新值、静止下半必须是旧值**（翻动上半=旧值、翻动下半=新值）。
- **对策**：照 §client.js 分区 4 的层表实现；只在 `changedSlots` 的位上渲染翻动层；翻动层 `key` 带 `${idx}-${from}-${to}`，否则 8→9→8 这种往返不会重播 `animation`。

### 7. 金额宽度抖动

- **现象**：`¥9.99 → ¥10.00` 时整行左右挤动，翻牌接缝位置跳一下。
- **根因**：靠内容撑宽；`1` 比 `8` 窄，`tabular-nums` 只能保证字形等宽，保证不了「位数变化」。
- **对策**：定宽槽位 `slotify`（`SLOT_COUNT = 9`，前导 `\u00a0` 补齐）；牌宽写死 `width:0.62em` 而不是由内容撑开；`font-variant-numeric: tabular-nums`；极端金额（≥9 字符）**不裁切**，宁可整行变宽也不丢 `¥` 和小数点。

### 8. 跨午夜算成全天 100%

- **现象**：白班 09:00–18:00，早上 08:00 或中午 12:00 显示日薪封顶 `¥454.54`，`progress` 恒 1。
- **根因**：用「当前时刻 < 下班时刻」决定是否回退一天（SalaryTick `app.py:74` 的真 bug，见 `docs/对标-网络.md` §1.3 实测表）。白班下班前该条件恒成立 → 窗口整体挪到昨天 → `elapsed` 永远 ≥ total。
- **对策**：见 `## calc 伪代码` ③④⑤——先判 `crossMidnight = startMin + totalMin > 1440`，只有跨午夜才看昨天那个窗口，且一律用绝对时间戳做差；`progress` 只由 `elapsed/totalMs` 夹紧得到。

### 9. 1e-9 没加 → 少一分钱

- **现象**：该显示 `¥1.15` 的地方显示 `¥1.14`；金额偶发比真值少 0.01 且一直少。
- **根因**：`1.15 * 100 === 114.99999999999999`，`Math.floor` 直接把 114.999… 砍成 114。
- **对策**：统一走 `trunc2(n) = Math.floor(Math.abs(n)*100 + 1e-9)/100`，并保留符号；`fmtMoney` 只用 `trunc2`，不要在别处再写一遍 `Math.floor(x*100)/100`。

### 10. NaN / `¥-0.00` / 三位小数

- **现象**：清空月薪输入框后金额变成 `¥NaN`；或截断后出现 `¥-0.00`；或某处漏出 `¥12.345`。
- **根因**：空串被 `+''` 转成 0 参与除法；`-0` 参与 `toFixed` 输出 `'-0.00'`；某处直接 `toFixed(3)` 或拼了原始浮点。
- **对策**：`calc` 入口 `Number.isFinite` 卫兵 + 全部返回安全值；`fmtMoney` 里 `v === 0 ? 0 : v` 把 `-0` 归一；金额一律经 `fmtMoney`，不许在组件里自己拼字符串。

### 11. 2 秒节拍与 220ms 动画抢跑

- **现象**：金额偶尔停在翻一半的状态；或两次翻页叠在一起像卡住。
- **根因**：新值在上一次动画还没结束时到达（切参数、切回标签页立刻补 tick、拖时间条）。
- **对策**：`FLAP_MS(220) < SETTLE_MS(2000)` 是前提；再来新值时直接摘掉旧翻动层、以新值重建，**不排队**；`prefers-reduced-motion` 时连翻动层都不渲染。

### 12. 写死颜色值

- **现象**：亮色主题下金额白字贴白底看不见、描边消失；或某处出现蓝紫色（别的插件的品牌色）。
- **根因**：直接写 `#fff` / `rgba(0,0,0,…)` 当文字、边框、背景。
- **对策**：只允许 7 个 `--dsw-alias-*` token；明暗过渡（翻牌下半页压暗）用 `color-mix(in oklab, var(--dsw-alias-bg-layer-2) 88%, #000)`，其中 `#000` **只作为混合用色**，不得单独做前景/边框/背景；不自建主题判断，跟随宿主。
