> 抓取时间 2026-10-25。只读源码，不复制代码：PayDance 是 AGPL-3.0-only（代码一律不抄，只借思路），SalaryTick 是 MIT，split-flap 参考 MIT。

## 一句话结论

计算骨架照 SalaryTick（`日薪 = 月薪 / 每月计薪天数`、`进度 = 已过计薪时长 / 总计薪时长`），但**班次归一必须照 PayDance**——SalaryTick 用时刻比较决定是否回退一天，我实测它把非跨午夜班次算成"全天恒 100%"，不能抄。
金额永远用墙上时钟重算、绝不累加；每一步都 `clamp(elapsed, 0, total)`，"上班前 = 0 / 收工 = 封顶"是夹紧的自然结果，不需要单独分支。
取整两边都在**渲染时**做四舍五入，我们按立项卡改成截断，但要加 `1e-9` 修正（`1.15 * 100 === 114.99999999999999`，直接 `floor` 会少一分）。
翻牌照 codemanshan/splitflap（MIT）的四层结构：静止上半=新值、静止下半=旧值、翻动上半=旧值下翻 0→-90°、翻动下半=新值上翻 90→0°。
落地要点：`perspective` 打在牌容器（240px），`transform-origin` 打在接缝（上半 `bottom center`／下半 `top center`），所有半页 `backface-visibility: hidden`，半程 110ms × 2 = 220ms、`cubic-bezier(.3,0,.2,1)`，只给变化位挂 animation，进位按"距个位几个数字位"错开 30ms。

## 1. SalaryTick（HanLoney/SalaryTick，Python + tkinter 单文件）

抓取路径：`https://raw.githubusercontent.com/HanLoney/SalaryTick/main/app.py`（HTTP 200，650 行，无子模块）。源码页面：<https://github.com/HanLoney/SalaryTick/blob/main/app.py>

### 1.1 计算核心（原文，app.py:60-89）

```python
def calculate_earnings(now, monthly_salary, workdays, start_clock, end_clock):
    daily_salary = monthly_salary / workdays                      # 68
    start_at = datetime.combine(now.date(), start_clock)          # 69
    end_at = datetime.combine(now.date(), end_clock)              # 70
    if end_at <= start_at:
        end_at += timedelta(days=1)                               # 72-73
    if now.time() < end_clock:                                    # 74  ← 见 1.3 的 bug
        start_at -= timedelta(days=1)
        end_at -= timedelta(days=1)
    total_seconds = (end_at - start_at).total_seconds()           # 78
    elapsed_seconds = (now - start_at).total_seconds()            # 79
    progress = min(1.0, max(0.0, elapsed_seconds / total_seconds))# 80
    ...
    return daily_salary * progress, daily_salary, progress, phase  # 89
```

### 1.2 六个问题的答案

**① 工作进度怎么算**：按"已过去的计薪秒数 / 总计薪秒数"，秒级连续浮点，不是按秒整数计数、也不是按分钟取整（app.py:78-80）。总计薪秒数直接从 `下班时刻 - 上班时刻` 的 datetime 差取，不是 `工时 × 3600` —— 好处是"24 小时班"和跨日归一自动一致，少一处可能的漂移源。

**② 上班前 / 下班后的值**：不做分支，用 `min(1.0, max(0.0, …))` 把进度夹到 [0,1]（app.py:80），金额就自然变成 0 或 `daily_salary × 1`。封顶值 = 日薪（app.py:89）。三态文案由夹紧后的 progress 反推：`progress <= 0` → "未开始"、`>= 1` → "今日已完成"（app.py:82-87）。

**③ 跨午夜班次**：`if end_at <= start_at: end_at += 1 day`（app.py:72-73）这条是正确的归一——下班时刻不晚于上班时刻就当跨日，班次长度因此变成 `24h - start + end`。但紧接的 `if now.time() < end_clock: 整体回退一天`（app.py:74-76）是错的，见 1.3。

**④ 取整方式**：`f"¥{earned:,.2f}"`（app.py:459）—— **四舍五入**，且在**每次渲染时**做（每 250ms tick 格式一次，app.py:472），没有任何中间取整，也没有截断。带千分位逗号。

**⑤ 边界输入兜底**：先把输入串当字符串处理再转 float，容忍千分位与空格：`float(self.salary_var.get().replace(",", "").strip())`（app.py:447）。守卫是 `monthly_salary < 0 or workdays <= 0 → raise ValueError`（app.py:449-450），即 **月薪 0 放行**（显示 0.00），**工作天数 0 拦截**（防除零）。时间由 `parse_clock` 严格按 `%H:%M` 解析，非法即抛 `ValueError`（app.py:55-57）。所有异常被同一个 `except (ValueError, TypeError)` 兜住，金额显示 `¥--`、状态显示"请检查设置"、并给一行错误提示（app.py:463-469）——**不崩、不显示 NaN、保留上一次的进度条为 0**。

**⑥ 配置持久化**：`%APPDATA%/SalaryTick/settings.json`（app.py:17-18），键名 snake_case 平铺：`monthly_salary / workdays / start_time / end_time / x / y / topmost`（app.py:614-623）。值存**原始输入字符串**而不是数字（app.py:616-619），所以非法输入能原样落盘、下次启动继续报错让人改。默认 `workdays = "21.75"`（app.py:46，法定月计薪天数折算值）。保存有 400ms 防抖：`after_cancel` 旧 job 再 `after(400, …)`（app.py:609-612）。加载时先铺默认值、再按 `settings.json → SalaryNow → SalaryWidget` 的顺序找第一个能解析的文件，整段 try 包住（app.py:632-643 + 19-22）。

### 1.3 我实测到的一个真 bug（重要，别抄）

`if now.time() < end_clock` 这条本意是"如果现在的时刻还没到下班点，说明当前处在昨天开始的那个班次里"，但它没区分"跨午夜班次"和"普通白班"。我按原文逻辑跑了几个时刻（月薪 21750、21.75 天、日薪 1000）：

| 班次 | 时刻 | 原逻辑 progress | 应有 |
|---|---|---|---|
| 09:00–18:00 | 08:00 | 1.0 ✗ | 0 |
| 09:00–18:00 | 12:00 | 1.0 ✗ | 0.333 |
| 09:00–18:00 | 19:00 | 1.0 | 1.0 |
| 22:00–06:00 | 23:30 | 0.1875 ✓ | 0.1875 |
| 22:00–06:00 | 02:00 | 0.5 ✓ | 0.5 |

原因：白班下 `now.time() < end_clock` 在**下班前的任何时刻**都成立（包括上班前），窗口整体回退一天，`elapsed` 于是永远 ≥ `total`，夹紧后恒为 1.0。只有跨午夜班次碰巧正确。**正确做法是用绝对时间戳判断窗口归属，不用时刻比较**（见 2.3 ③）。

### 2.2 计算核心（snapshot.ts:94-122，摘）

```ts
const totalWorkMs = spans.reduce((s, [a, b]) => s + Math.max(0, b.getTime() - a.getTime()), 0);
if (totalWorkMs <= 0) return { ...emptySnapshot, status: "invalid-config" };   // 98
const elapsedWorkMs = spans.reduce((sum, [start, end]) => {
  const spanMs = end.getTime() - start.getTime();
  return sum + clamp(nowMs - start.getTime(), 0, spanMs);                     // 105  ← 关键
}, 0);
const hourlyRate = dailySalary / workHours;                                    // 110
const progress = clamp(elapsedWorkMs / totalWorkMs, 0, 1);                     // 113
return { earnedToday: dailySalary * progress, ... };                           // 122
```

### 2.3 六个问题的答案

**① 进度口径**：和 SalaryTick 同构——"已过计薪毫秒 / 总计薪毫秒"，毫秒级连续量（snapshot.ts:105/113），金额 `dailySalary * progress`（snapshot.ts:122）。**核心不取整**，保留浮点一路到渲染。

**② 上班前 / 下班后的值**：靠 `clamp(now - start, 0, spanMs)` 保证每个时间段贡献非负且不超额（snapshot.ts:105），于是 `elapsed` 天然落在 `[0, total]`。状态判断不是比时刻，而是比 `elapsed`：`elapsed <= 0` → `before-work`、`elapsed >= total` → `after-work`、否则看是否落在某个 span 内 → `working`（snapshot.ts:38-48）。封顶由 clamp 保证，无额外分支。

**③ 跨午夜判定与归一**：三层都不靠时刻比较。
- 分钟数归一：`normalizeWorkEnd = end < start ? end + 1440 : end`（time.ts:23-24）——把时刻先化成"当天第几分钟"，跨日就 +1440，比拼 datetime 少踩时区/DST 的坑。
- 窗口解析：`resolveWorkSpans` 先算**昨天**的窗口，若 now 落在其中就返回昨天窗口；否则算今天的窗口；再做一次兜底——如果昨天窗口在今天结束、且今天的窗口还没到，仍返回昨天窗口（work-spans.ts:94-109）。
- `now` 在窗口内的判断用 `getTime()` 直接比大小（work-spans.ts:68-76）。

这套组合对白班和夜班都正确；SalaryTick 缺的正是"候选窗口"这一步。

**④ 取整方式**：同样是**四舍五入、渲染时取整**，但走 `Intl.NumberFormat`：`{minimumFractionDigits: 2, maximumFractionDigits: 2, useGrouping: false}`（money-format.ts:13-15），并缓存 formatter 按 locale 复用（money-format.ts:7-18）。无千分位分隔符。

**⑤ 边界兜底**：`validateSalaryConfig` 一次收集**所有**问题而不是抛第一个（validation.ts:41-100），返回 `SalaryConfigIssue[]`，任一非空就整体退化成 `emptySnapshot` + `status: "invalid-config"`（snapshot.ts:93-96），界面显示"配置待修正"。具体判据：`hasPositiveNumber = Number.isFinite(v) && v > 0`（validation.ts:19）——**月薪 0 判非法**（和 SalaryTick 相反）；每月工作天数 `> 31` 判非法（validation.ts:17/65）；`start === end` 判非法（validation.ts:86），即**拒绝 24 小时班**；时间解析用 `/^(\d{1,2}):(\d{2})$/` 再查 `0–23 / 0–59`，失败返回 `NaN`（time.ts:9-21）；最后还有一道 `totalWorkMs <= 0` 的运行期兜底（snapshot.ts:98）。

**⑥ 配置持久化**：桌面端 `%APPDATA%\com.masterbao.paydance\salary-settings.json`（Tauri Store），Web Preview 用 `localStorage`；文件名与**键名集中常量表** `settingsStoreKeys`（`src/lib/settings-store.ts:3-19`），含 `config / mainPosition / miniPosition / miniSize / miniOpacityPercent / themeMode / locale / settingsVersion …`。配置本身是一个 `config` 键下的对象，另有独立 `settingsVersion`，迁移用 `settingsSchemaVersion = 4` + 逐版本迁移函数表（`src/lib/settings-migration.ts:15/71-75`）。加载时**逐字段**校验并各自回退到默认值，坏的单个字段不牵连整份配置，同时回传 `recoveryReason`（`invalid-values` / `future-schema`，settings-migration.ts:77-160/180）供 UI 提示。读失败会备份原文件为 `salary-settings.json.bak-<时间戳>` 再用默认值重建（FAQ.md「设置文件无法读取怎么办」）。

| 问题 | SalaryTick | PayDance | 我们（按立项卡） |
|---|---|---|---|
| 进度口径 | 秒级 `elapsed/total` | 毫秒级 `elapsed/total` | 秒级，同一个式子 |
| 上班前 | 夹紧到 0 | `elapsed<=0` → 0 | 0.00 + 灰字"还没上班" |

| 持久化 | 单个 JSON，原始字符串 | JSON + 键表 + schema 版本 + 逐字段兜底 | localStorage 分键 + 前缀 |

## 4. 翻牌动画：可直接抄的结构

### 4.1 参考来源

[codemanshan/splitflap](https://github.com/codemanshan/splitflap)（React + CSS 3D，无 canvas，MIT）。抓的是两个文件：

- `registry/split-flap/split-flap.css`（6.4KB，纯 CSS 机制）<https://raw.githubusercontent.com/codemanshan/splitflap/main/registry/split-flap/split-flap.css>
- `registry/split-flap/split-flap-slat.tsx`（单张牌的 React 状态机）<https://raw.githubusercontent.com/codemanshan/splitflap/main/registry/split-flap/split-flap-slat.tsx>

另有 [GenbuHase/PatapataClock](https://github.com/GenbuHase/PatapataClock)（纯 CSS 3D 翻页时钟）可作交叉验证，机制一致。

### 4.2 四层叠放与角色（这是最容易搞反的地方）

一张牌由**两个静止半页 + 两个翻动半页**叠成，静止态只露出前两个：

| 层 | 显示哪个数字 | 位置（z-index） | 什么时候可见 |
|---|---|---|---|
| ① 静止上半 `.sf-half--top` | **新值**的数字（翻动期）/ 当前值（静默期） | 0 | 一直在，被 ③ 盖住 |
| ② 静止下半 `.sf-half--bottom` | **旧值**的数字 | 0 | 一直在，静默期露出 |
| ③ 翻动上半 `.sf-flip--top` | **旧值**的数字 | 2 | 翻动前半程，沿底边下翻 0→-90° |
| ④ 翻动下半 `.sf-flip--bottom` | **新值**的数字 | 2 | 翻动后半程，从 +90° 上翻回 0° |

时序：③ 先翻（0–110ms），把旧值的上半页翻下去，露出①里已经准备好的新值上半；③ 到底后 ④ 才从侧立状态展开（延迟 110ms，110–220ms），把旧值的下半页盖住。**如果①里放的是旧值、②放的是新值，你会看到"翻完之后又跳回去一次"，这是唯一一个必须记住的方向。**

### 4.3 可直接抄的 DOM + CSS

`perspective` 打在**牌容器**上（240px，参考实现原值，见 split-flap.css:45）；`transform-origin` 打在**接缝**上（上半 `bottom center`、下半 `top center`，split-flap.css:139/150）；`backface-visibility: hidden` 打在**所有半页**上（split-flap.css:67-68/127-128），理由是旋转到 ±90° 附近时 `preserve-3d` 会把背面（镜像的数字）也画出来，出现"反字透出"；再补一个 `translateZ(0)` 强制成独立合成层，修 Safari 的 backface 失效（split-flap.css:69 的作者注释）。

```html
<!-- 一位十进制。静止态只渲染 ①②；翻动时临时挂上 ③④，动画结束由 JS 摘掉。 -->
<span class="sf-slat" aria-hidden="true">
  <!-- ① 静止上半：翻动期显示【新值】，静默期显示当前值 -->
  <span class="sf-half sf-half--top"><span class="sf-glyph">9</span></span>
  <!-- ② 静止下半：翻动期显示【旧值】，静默期显示当前值 -->
  <span class="sf-half sf-half--bottom"><span class="sf-glyph">8</span></span>
  <!-- ③ 翻动上半：旧值 8，沿底边下翻 0 → -90° -->
  <span class="sf-flip sf-flip--top"><span class="sf-glyph">8</span></span>
  <!-- ④ 翻动下半：新值 9，从 +90° 翻回 0 -->
  <span class="sf-flip sf-flip--bottom"><span class="sf-glyph">9</span></span>
</span>
```

### 4.4 只翻「变了的位」

三层逻辑，都是纯函数，可以放进 client.js 的纯函数层：

```js
// ① 金额 → 定宽位数组。位数固定，小数点和小数位都占格，
//    这样 ¥9.99 → ¥10.00 时不会因为多一位导致整行抖动。
const SLOT_COUNT = 9;               // ¥ + 3 整数 + . + 2 小数 = 7，留 2 格余量
const slotify = (text) => {
  const padded = text.padStart(SLOT_COUNT, '\u00a0');   // 前导用不换行空格，不显示但占位
  return [...padded].slice(-SLOT_COUNT);
};

// ② 只挑真正变了的位（非数字位永远不翻）
const changedSlots = (prev, next) => {
  const out = [];
  for (let i = 0; i < next.length; i += 1) {
    if (prev[i] !== next[i] && /\d/.test(next[i])) out.push(i);
  }
  return out;
};

// ③ 进位从右往左逐位翻：延迟 = 这一位右边还有几个数字位 × 30ms
//    ¥19.99 → ¥20.00 时，个位先翻、十位次之、百位最后，形成级联感。
//    非进位的单点变化（¥12.33 → ¥12.34）只有一位变，延迟天然是 0。
const STAGGER_MS = 30;
const MAX_STEPS = 4;                 // 最多错开 120ms，再多就显得拖沓
const delayOf = (index, next) => {
  let rightDigits = 0;
  for (let i = index + 1; i < next.length; i += 1) if (/\d/.test(next[i])) rightDigits += 1;
  return Math.min(rightDigits, MAX_STEPS) * STAGGER_MS;
};
```

React 侧要点：

- **没变的位不要重挂**。只对 `changedSlots` 里的位渲染 `.sf-flip` 两层，其余位保持原 DOM 不动，脏区最小。
- **翻动层的 key 必须随 `(旧值, 新值)` 变**，例如 ``key={`${idx}-${from}-${to}`}``，否则新旧值相同的两次变化（例如 8→9 之后又回到 8）不会重播 CSS animation。
- **220ms 必须短于结算节拍 2000ms**，动画一定能在下一次 tick 前收尾；但要做一层保护：若上一次动画未结束又来了新值，直接摘掉旧翻动层、以新值重建，不要排队。
- 整体上浮用同一个开关量驱动，别写在 keyframes 里：参考 PayDance 的 `is-ticking` —— 值一变就 `requestAnimationFrame` 置 true、220ms 后置 false，CSS 只挂 `transform: translateY(-2px)` 的 transition（RollingAmount.vue:63-76 / 177-180）。

### 4.5 时长 / 缓动 / 等宽 / 降级

- **时长**：参考实现是 50ms 折叠 + 60ms 展开（split-flap.css:140/152），总共 110ms，偏脆。立项卡要求 180–260ms，取 **220ms（半程 110 + 110）**——比参考慢一倍，翻页看得清、不会模糊；超过 260ms 会在 2 秒节拍里显得"没停稳"。
- **缓动**：立项卡指定 `cubic-bezier(0.3, 0, 0.2, 1)`（快出慢收），比参考的 `ease-in` / `ease-out` 更有"卡纸落下"的手感。两段用同一条曲线，不要给第二段换成 `ease-in`，否则接缝处会有一下顿。
- **等宽**：`font-variant-numeric: tabular-nums` 是必须的，但**不够**——它只保证字形宽度一致，牌本身仍要写死 `width: 0.62em`。理由：不等宽字体下 `1` 比 `8` 窄，`¥11.11` 和 `¥88.88` 的行宽会差几个像素，翻牌位会左右挤动；写死牌宽后，宽度只由"位数"决定，而位数又由定宽 slot 兜住（4.4 ①）。
- **降级**：CSS 侧 `@media (prefers-reduced-motion: reduce)` 直接 `display: none` 掉翻动层（参考实现 split-flap.css:191-196 的做法），JS 侧同时用 `matchMedia('(prefers-reduced-motion: reduce)').matches` 判断，为真就不渲染翻动层、直接把当前值设成新值（split-flap-slat.tsx 的 `prefersReduced` 分支）——两层都做，只做 CSS 的话逐位延迟还在，仍会有"卡顿感"。

## skip

1. **午休剔除 / 双段工作区间**（PayDance 的两 span 方案，work-spans.ts:40-66）。立项卡 §8 明确不做；代价是 12:00–13:30 金额继续涨、和真实到手有偏差，这个偏差立项卡已接受，为它引入双区间会让我们的 `calc` 从 15 行涨到 60 行。
2. **按星期几配工作日 + "今日休息"状态**（`workdays: [1,2,3,4,5]`，config.ts:56）。要真做就得再维护一张节假日表，否则国庆照样满格跳动；我们的模型是"月薪摊到每月工作天数的日均"，本来就不承诺排班正确。
3. **动态结算节拍**（PayDance 按"再赚一分钱需要多久"算下一次唤醒，夹在 120–1000ms，useSalaryTicker.ts:15-46）。立项卡 §4 钉死 2 秒格点、§9.4 要求"10 秒跳 5 次左右"；动态间隔会让它变成几乎连续滚动，验收直接不过。
4. **Solari 的"只进不退、一次只翻一格、必要时连翻多格"机制**（`computeFlipCount` / `minFlips`，split-flap-slat.tsx:14-19）。我们每 2 秒才变一次值，一次到位反而是对的；连翻会让动画永远追不上新值，还会在 2 秒节拍里显得卡顿。
5. **千分位逗号**（SalaryTick 的 `:,.2f`，app.py:459）。翻牌是定宽位，逗号位要么常驻要么让位宽跳变；`¥1,234.56` 比 `¥1234.56` 多一格，260px 宽的板子放 3 位整数已经到顶。
6. **动态字号自适应**（SalaryTick 按字符数在 36/31/26 三档切换，app.py:474-480）。翻牌位宽写死、位数用定宽 slot 兜住之后不需要它；引入它会让牌高跟着变，翻页的接缝位置会跳。
7. **glow / 星点 / 流光 / 金色呼吸**（SalaryTick 的 8 层 glow 文本 + 6 颗正弦闪烁星，`_animate_gold_effect`）。立项卡 §6 只要求"整体 1–2px 上浮"的次要动效；常驻闪烁会和每 2 秒的翻页抢注意力，而且每秒 80ms 一次的 canvas 重绘在 overlay 层上是纯浪费。
8. **桌面壳能力**：置顶、托盘、开机自启、透明度滑杆、迷你窗独立位置（PayDance `MiniOpacityPanel` / `useAutostart` / `tray.rs`）。我们是网页 overlay 里的一个浮层，这些一个都用不上，多个窗口位置反而和"拖动 + 折叠"两套状态打架。
9. **`start === end` 判非法的策略**（validation.ts:86）。我们不让用户填下班时刻，下班由"上班 + 每日工时"推出，`end === start` 只可能来自工时 = 0 或工时 = 24；前者该拦，后者是合法的 24 小时班，直接照搬会把合法输入判死。改成"工时 ∈ (0, 24] 且 `totalSeconds > 0`"。

## differ

1. **取整方向：我们截断，两边都四舍五入。** SalaryTick `f"¥{earned:,.2f}"`（app.py:459）、PayDance `maximumFractionDigits: 2`（money-format.ts:13-15）都是四舍五入。立项卡 §4 要求截断（避免 0.005 显示成 0.01 的跳变错觉），实现要写成 `Math.floor((earned + 1e-9) * 100) / 100`——不加 `1e-9`，`1.15 * 100` 在 IEEE754 下是 `114.99999999999999`，`floor` 会给成 1.14，比四舍五入还难看。
2. **班次归一用绝对时间 + 候选窗口，不用时刻比较。** SalaryTick 的 `now.time() < end_clock`（app.py:74）在非跨午夜班次下会把整个窗口挪到昨天，实测白班任意时刻 progress 恒为 1.0（见 1.3 表）。这是我们唯一"明确不抄"的计算逻辑，改成 PayDance 的窗口解析。
3. **非法配置不进运行态。** 两边都是运行时退化成 `¥--` / "配置待修正"（app.py:463-469、snapshot.ts:93-96）。立项卡 §5 规定"首次出现 = 设置态"，所以非法输入根本不该跑起来：设置态行内报错 + 禁用"开始跳"，运行态只保留一层 `totalSeconds <= 0 → 返回 0` 的哑防御。少一个状态、少一批文案。
4. **运行态只要我们三态（未上班 / 进行中 / 收工），不是 PayDance 的六态。** 它的 `rest-day` / `lunch-break` / `invalid-config` 对应的功能（按星期排班、午休、运行期非法配置）我们全部 skip，照搬会留下一半永远走不到的分支。
5. **持久化用 localStorage 分键 + `dsh.salary-flap.v1.` 前缀，不是单文件单对象。** 两边的 JSON 文件是它们独占的（`%APPDATA%/SalaryTick/settings.json`、`salary-settings.json`），而浏览器 localStorage 跟 Harness 其他插件共用同一个命名空间，不前缀就等着撞键。另外设置、位置、折叠态三者更新频率差一个数量级，分键可以只写变的那一个（键名约定见 `docs/架构.md`）。
6. **翻牌，不是数字条滚动。** PayDance 的数字动画是 odometer：一列 0–9 排好，靠 `translate3d(0, -{digit}em, 0)` 位移（RollingAmount.vue:119-122 与 224-227，`transition: transform 260ms cubic-bezier(0.16, 0.84, 0.28, 1)`），本质是一段连续位移。立项卡 §6 要求的是"上半页下翻 + 下半页翻出"的两段式分片翻牌——那是 3D 折叠，不是位移，两者 DOM 和性能特征都不同：翻牌靠 `perspective` + `rotateX`（4 个层），odometer 靠一个 `overflow: hidden` 容器 + 一条 10 倍高的数字带。
7. **位数固定为 9 格（含前导占位），不做位数自适应。** 两边都靠内容撑宽（SalaryTick 甚至按字符数换字号）。固定 slot 的好处是 `¥9.99 → ¥10.00` 整行不抖、翻页接缝位置永远一致，代价是 ¥ 前面有 2 格不换行空格的视觉留白——在 260px 的板子上可以接受。
8. **结算金额只截断、不累计误差。** 两边都没有累计器（每次都重算），这点我们一致；不同在于我们把"每 2 秒结算一次"实现成"每 2 秒取一次 `floor` 快照"，而不是"每 2 秒在上一值上加 `时薪/1800`"。后者哪怕用整数分也会在长时间挂机后与真实值偏离，且改参数时必须回算历史。
